## 二、赛道选择结论

### 结论：报名 **方向 2「AI 赋能经营管理」**，细分定位为「研发管理 / 科研项目全生命周期管理」

### 三方向对比

| | 方向 1：AI 赋能科研生产 | 方向 2：AI 赋能经营管理 | 方向 3：AI+创新创意 |
| --- | --- | --- | --- |
| 赛道要求 | 研发设计、仿真验证、生产制造、工艺优化、试验测试 | 战略、经济运行、人力资源、财务、**研发管理**、采购、内控、合规、风控、审计等 | 智能原生新概念/新方法/新技术/新产品，侧重原创性、前沿性、跨界复用性，**原理层面革新** |
| 本平台匹配度 | ❌ 低 | ✅ **高** | ⚠️ 中（风险高） |
| 判断依据 | 平台是**管理类**系统，不是设计/仿真/工艺工具，硬套会严重失分「场景契合」30% | 平台内核正是"研发管理"+"跨部门协同"，且能覆盖该方向 4 个重点中的 3 个 | 方向 3 的 35% 权重压在"技术原创性/原理级创新"，纯应用层平台难以支撑，易被专业评委质疑 |

### 为什么方向 2 是最优解

该方向明确的四个重点，本平台**命中 3 个**：

| 方向 2 的重点 | 平台对应能力 | 落地程度 |
| --- | --- | --- |
| （2）**决策数据驱动**，从经验判断→数据驱动、模型辅助 | 部门效能大盘（雷达图 + 各项目效能对比柱状图）、指标"期望值 vs 实际值"红黄绿灯 | ✅ 图表框架已就绪 |
| （3）**风险内控闭环**，从事后检查→事前预警/事中管控/事后追溯 | 产品健康度（正常/风险/延期）、阶段门径卡点预警、效能瓶颈高亮预警 | ✅ 模型已建立 |
| （4）**制度流程自跑**，"人找制度"→"制度找人、流程自跑"；**基层减负**与流程再造 | 阶段门径必填文档清单 + 评审流转、AI 自动生成周报 + 一键分发干系人 | ✅ 主流程已贯通 |
| （1）数据贯通治理，打通数据底座 | 创意/产品/部门/指标/周报五类对象的贯通（当前为本地数据，需在申报材料中补"数据底座"设计） | ⚠️ 需补强 |

### 差异化叙事（应对维度 1 的"竞品对标与差异化优势"）

> 市面上绝大多数"研发管理"产品是**单维度**的：要么管项目进度（Jira / 禅道），要么管文档（Confluence），要么管绩效（HR 系统）。
> 本平台的差异点是**三维联动**——「**创意（Idea）— 产品（Product）— 部门（Department）**」：
> 一线的创意可以直接孵化为产品线，产品线在立项时**反向给每个参战部门设定效能指标目标**，部门的效能达成情况再**回灌到项目看板做预警**。
> 这是一条自带闭环的"创新链"，解决了矩阵式研究院最痛的问题：**跨部门项目里，谁该为指标负责、指标达没达成、不达成该在什么时点预警。**

**一句话定位（可直接用于报名表/PPT 封面）**：
> 面向矩阵式研发组织的 AI 创新孵化与效能度量中台——让每一个创意都能跑通"想法 → 立项 → 门径 → 量产"，并让每一个参战部门的效能可量化、可预警、可问责。

**建议也准备一句"科研生产"语境的柔化表述**（因承办方主业是装备研制，评委可能偏好该语境）：
> 面向科研生产任务的产品化转型管理平台，将创意孵化、阶段门径（EVT/DVT/MP）、打样直通率等研制关键指标纳入统一数字化闭环。

## 三、平台通用命名方案

### 命名原则

1. **完全通用**：不绑定任何单位简称（原"NHY / nh-ai-platform"属单位专属，无法对外）
2. **名称即内核**：能体现"创意孵化 + 阶段门径 + 效能度量"三者之一或全部
3. **央企语境**：正式、稳重、有体系感与科技感，避免互联网化过度
4. **易传播**：中文好读、好写、好解释；最好有干净的英文名与缩写
5. **低撞名风险**：避免与知名企业/产品重名

### ✅ 最终选定：创擎 · 创新全生命周期平台（InnoTorque）

| 项目 | 内容 |
| --- | --- |
| 中文名 | **创擎** |
| 英文名 | **InnoTorque** |
| 完整称谓 | 创擎 · 创新全生命周期平台 |
| 主标语 | **驱动组织创新的引擎** |
| 命名依据 | **创**（创意 / 创新）+ **擎**（引擎 / 擎举），即"创新引擎"：平台把分散的创意、产品、部门效能"擎"起来，形成一条可推进、可度量、可问责的创新链 |

## 四、评分维度对标打法（核心）

### 维度 1：场景契合与发展前景（30%）

| 评委要什么 | 我们怎么答 |
| --- | --- |
| 贴合真实业务场景、解决痛点 | 讲透三大痛点：① 一线有洞察但表达不出 PRD，好想法难孵化；② 原型→量产缺统一阶段卡点与文档规范，PMO 汇总靠人肉；③ 产品信息分散，向上汇报/跨部门沟通反复整理、口径不一 |
| **形成量化效益** | 必须准备数字。建议口径：创意提案提交量提升、PRD 撰写耗时从 X 天→Y 分钟、PMO 周报汇总工时下降 X%、阶段评审因文档不全被打回次数下降 X% |
| 市场空间与产业链定位 | 定位"企业级研发管理软件 / PLM 细分"，对标 Jira、禅道、飞书项目、PingCode、Confluence；强调面向**矩阵式科研组织**的垂直细分市场 |
| 竞品对标与差异化 | 用上文「三维联动」叙事，一句话讲清与 Jira/禅道的本质区别 |

### 维度 2：创新性（35%，最高权重）

| 评委要什么 | 我们怎么答 |
| --- | --- |
| 应用创新性（落地业务场景、新流程新模式） | **"创意—产品—部门"三维联动机制**是核心创新点：立项时反向设定部门指标目标，形成"目标设定→过程追踪→瓶颈预警→复盘"闭环。这是通用项目管理工具没有的 |
| 技术先进性 | 讲清三层 AI 能力：① AI 引导式追问（把模糊想法结构化）；② AI PRD 自动生成 + 局部重绘（对话式改文档）；③ AI 周报自动汇总（多源数据→结构化输出）。补充 RAG/大模型选型、Prompt 工程方法 |
| **自主可控与国产化** | 这是电科场景的加分重点，必须写：底层大模型采用**国产私有化部署**（如 DeepSeek / 通义 / 文心 / 电科自研模型），全栈信创（麒麟 OS + 达梦/人大金仓 + 鲲鹏/飞腾），数据不出内网 |
| 知识产权 | 准备软件著作权登记材料、核心机制专利点梳理（如"一种基于三维联动的研发效能指标回灌方法"） |

### 维度 3：实施保障（20%）

| 评委要什么 | 我们怎么答 |
| --- | --- |
| 创意→原型→试点→规模化路径 | 三阶段：**原型**（已完成，可现场演示）→ **试点**（选 1–2 个研究院/产品线，3–6 个月，跑通 1 条完整产品线）→ **规模化**（纳入集团统建系统，全院/多单位推广） |
| 关键节点明确 | 给出里程碑表（时间点 + 交付物 + 验收标准） |
| 算力与运维成本可控 | 给出量化估算：私有化部署单节点算力需求、日均推理 Token 消耗、人均年成本；强调**推理成本随模型蒸馏/量化持续下降** |
| 未来 3–5 年规划 | 3 年：单院覆盖 + 指标库标准化；5 年：集团级研发效能数据底座，支撑跨单位创新协同与资源调配 |

### 维度 4：团队情况（15%）

- 提前准备：核心成员既有成果（论文/专利/已上线系统）、能力矩阵（AI 算法 + 前端/后端工程 + 产品/研发管理业务专家）**跨界互补性**
- 现场汇报：Demo 现场跑通完整业务链路（新建创意 → AI 生成 PRD → 评审通过 → 自动立项 → 阶段门径 → 生成周报），比 PPT 截图有说服力得多
